## 🎨 总体设计原则

### 设计目标

✅ **清晰易读**: 信息层次分明，视觉引导流畅
✅ **专业美观**: 技术感配色，符合学术规范
✅ **模块化**: 每个组件独立清晰，易于理解
✅ **无遮挡**: 优化布局和连线，避免视觉混乱

### 核心设计理念

```
信息 > 美观 > 复杂度
简洁 > 华丽
功能 > 装饰
```

## 📐 布局优化策略

### 1. 整体布局原则

#### 信息流向

```
从左到右，从上到下
Input → Processing → Output
```

#### 空间分配

```
标题区域:    20px  (顶部)
主内容区域:  800px (中间，主要组件)
底部总结:    60px  (性能指标、关键信息)
左右边距:    80px  (留白，避免拥挤)
```

#### 模块间距

```
水平间距: 40-60px (组件之间)
垂直间距: 40-60px (同级组件)
         140-200px (不同层级)
```

### 2. 各模型布局特点

#### π₀* 0.6 布局 (1600×1200)

```
层级1 (100-280px):    标题 + 输入层
层级2 (100-320px):    VLM + Action Expert (并列)
层级3 (380-620px):    Value Function + RECAP (并列)
底部 (680-800px):     任务 + 性能指标

布局特点:
- 强调三大核心模块的并列关系
- RECAP循环突出训练流程
- 任务评估独立展示
```

#### SmolVLA 布局 (1600×1400)

```
层级1 (20-80px):      标题 + 副标题
层级2 (120-380px):    输入 → VLM → Action Expert (流水线)
层级3 (430-690px):    Async Inference + Community Data + Performance (三并列)
底部 (740-860px):     创新点 + 架构注释

布局特点:
- 强调流水线式的处理流程
- 异步推理突出创新
- 社区数据体现民主化
```

#### Evo-1 布局 (1600×1500)

```
层级0 (100-300px):    两阶段训练横幅（强调核心创新）
层级1 (340-490px):    输入层
层级2 (340-620px):    VLM → Integration → Action (流程清晰)
层级3 (540-720px):    Semantic Preservation (语义保留说明)
层级4 (760-980px):    性能展示（详细的结果对比）
底部 (1020-1130px):   对比 + 统计信息

布局特点:
- 两阶段训练放在最顶部（核心卖点）
- 语义保留单独强调（关键创新）
- 性能展示最详细（证明效果）
```

### 3. 避免遮挡的布局技巧

#### 技巧1: 网格对齐

```
使用10px网格对齐:
- 所有组件左上角对齐网格点
- 宽度和高度为10的倍数
- 间距统一为40px, 60px, 80px等
```

#### 技巧2: 层级分离

```
垂直分层:
层级1: y = 100-300
层级2: y = 340-620 (间隔40px)
层级3: y = 660-900 (间隔40px)

确保各层不重叠，视觉清晰
```

#### 技巧3: 水平留白

```
左边距: 80px
右边距: 80px
中间间距: 60-80px

避免组件靠边，保持呼吸感
```

## 🔗 连线规范

### 1. 连线类型

#### 实线（Solid Line）
```
用途: 主要数据流
颜色: 与起点模块颜色一致
粗细: 3px (主流程), 2px (次流程)
样式: orthogonalEdgeStyle (直角转折)
```

#### 虚线（Dashed Line）
```
用途: 辅助流程、反馈回路
颜色: 与起点模块颜色一致
粗细: 2px
样式: orthogonalEdgeStyle + dashed=1
```

### 2. 连线颜色

| 起点模块 | 连线颜色 | 含义 |
|---------|---------|------|
| Input | #4CAF50 / #3F51B5 / #FF6F00 | 输入数据流 |
| VLM | #2196F3 / #00897B / #7B1FA2 | 特征流 |
| Action Expert | #FF9800 / #EF6C00 / #F57F17 | 动作流 |
| Value Function | #9C27B0 | 价值引导 |
| RECAP | #E91E63 | 训练循环 |

### 3. 连线路径优化

#### 原则: 避开其他组件

```
好的路径:
┌─────┐     ┌─────┐
│  A  │────→│  B  │
└─────┘     └─────┘
    ↓
    │ (空白区域)
    ↓
┌─────┐
│  C  │
└─────┘

坏的路径:
┌─────┐     ┌─────┐
│  A  │────→│  B  │
└─────┘  │  └─────┘
         ↓ (遮挡B)
      ┌─────┐
      │  C  │
      └─────┘
```

#### 具体实现

```xml
<mxCell id="arrow" style="edgeStyle=orthogonalEdgeStyle;...">
  <mxGeometry relative="1" as="geometry">
    <Array as="points">
      <mxPoint x="420" y="205" />  <!-- 中间转折点 -->
      <mxPoint x="420" y="250" />  <!-- 避开组件 -->
    </Array>
  </mxGeometry>
</mxCell>
```

### 4. 箭头样式

```
标准箭头: 默认三角形
粗度: 与连线一致
填充: 与连线颜色相同
```

## 🎯 各模型特色设计

### π₀* 0.6 特色

**核心亮点: RECAP训练循环**

```
设计特点:
1. RECAP模块使用独特的粉色系，突出创新
2. 价值函数与VLM的虚线连接，强调反馈
3. 任务评估单独列出，展示实际应用
4. 底部性能横幅，一目了然
```

**关键标注**:
- 优势条件化 (Advantage Conditioning)
- 价值函数引导 (Value Guidance)
- 专家干预 (Expert Interventions)
- 2× 性能提升标注

### SmolVLA 特色

**核心亮点: 异步推理 + 社区数据**

```
设计特点:
1. 异步推理模块详细展开，显示创新性
2. 社区数据突出开源生态
3. 效率指标多处标注（40%更快, 6×更少内存）
4. 层跳过、Token减少等技巧明确标识
```

**关键标注**:
- Layer Skipping (N=L/2)
- Async Inference (g=0.7)
- Community Datasets (481个)
- 10× smaller than competitors

### Evo-1 特色

**核心亮点: 两阶段训练 + 语义保留**

```
设计特点:
1. 两阶段训练在顶部大横幅，最显眼
2. 语义保留单独模块，实验证明清晰
3. InternVL3 原生多模态特性强调
4. 性能对比最详细，三个benchmark全面展示
```

**关键标注**:
- Native Multimodal (不是后期对齐)
- Two-Stage Training (渐进式)
- Semantic Preservation (实验验证)
- SOTA without pretraining (核心卖点)

## 📚 使用指南

### 1. 在Draw.io中打开

#### 步骤:
```
1. 打开 Draw.io (https://app.diagrams.net/)
2. File → Open from → Device
3. 选择对应的 .drawio 文件
4. 开始编辑
```

### 2. 编辑技巧

#### 修改文本
```
双击任何文本框 → 直接编辑
字体大小: 11-14px (内容), 24px (标题)
字体: 默认系统字体，支持中英文
```

#### 调整颜色
```
选中组件 → 右侧属性面板
填充色: fillColor
边框色: strokeColor
文字色: fontColor
```

#### 添加组件
```
从左侧模板库拖拽
或复制现有组件 (Ctrl+C, Ctrl+V)
使用对齐工具: Arrange → Align
```

### 3. 导出选项

#### 导出为图片
```
File → Export as → PNG/JPEG/SVG
建议设置:
- PNG: 300 DPI, 透明背景
- SVG: 矢量图，可缩放
```

#### 导出为PDF
```
File → Export as → PDF
适合论文使用
```

### 4. 团队协作

#### 分享编辑
```
File → Share
生成分享链接
实时协作编辑
```

#### 版本控制
```
File → Version History
查看历史版本
恢复到之前的状态
```

## 💡 最佳实践

### DO ✅

1. **保持一致性**: 同类模块使用相同配色
2. **留白充足**: 避免组件过于拥挤
3. **层次清晰**: 使用颜色和大小区分重要性
4. **标注明确**: 关键参数和创新点要突出
5. **路径优化**: 连线避开其他组件
6. **对齐整齐**: 使用网格和对齐工具
7. **字体统一**: 不要混用多种字体
8. **Emoji适度**: 点缀用，不要过多

### DON'T ❌

1. ❌ 颜色过多（超过6种主色系）
2. ❌ 文字过小（<10px难以阅读）
3. ❌ 连线交叉遮挡
4. ❌ 组件重叠
5. ❌ 边距不一致
6. ❌ 信息密度过高
7. ❌ 使用纯黑或纯白背景
8. ❌ 忽略视觉层次

## 🔧 技术细节

### Draw.io XML 结构

```xml
<mxfile>
  <diagram name="模型名称" id="唯一ID">
    <mxGraphModel>
      <root>
        <mxCell id="0"/>  <!-- 根节点 -->
        <mxCell id="1" parent="0"/>  <!-- 画布 -->

        <!-- 组件定义 -->
        <mxCell id="component" value="文本"
                style="样式字符串"
                vertex="1" parent="1">
          <mxGeometry x="100" y="100" width="200" height="60"/>
        </mxCell>

        <!-- 连线定义 -->
        <mxCell id="edge" style="连线样式"
                edge="1" parent="1"
                source="起点ID" target="终点ID">
          <mxGeometry relative="1" as="geometry">
            <Array as="points">
              <mxPoint x="x坐标" y="y坐标"/>
            </Array>
          </mxGeometry>
        </mxCell>
      </root>
    </mxGraphModel>
  </diagram>
</mxfile>
```

### 样式字符串格式

```
属性1=值1;属性2=值2;...

常用属性:
fillColor=#FFFFFF    - 填充色
strokeColor=#000000  - 边框色
fontColor=#000000    - 文字色
fontSize=12          - 字体大小
fontStyle=0/1/2/3    - 普通/粗体/斜体/粗斜体
rounded=0/1          - 直角/圆角
whiteSpace=wrap      - 文字换行
html=1               - 支持HTML
align=left/center/right
verticalAlign=top/middle/bottom
strokeWidth=1        - 边框粗细
```
